# 构思与结构：从阅读欲望开始

## 什么时候读

用户要新作、长篇大纲、章节重排或重建主线时读取。只改几句台词时不要开启整套流程。

## 1. 找到作品的发动机

先用实际处境回答：“玩家为什么愿意和这些人再待一场？”可能是好奇、依恋、喜剧默契、恐惧、欲望、探索或解题。主题可在后续浮现，不强迫先写中心思想。

把设定变成会持续产生事件的关系。例如：一人想证明自己不再需要帮助，另一人想通过帮忙保住自己的位置。两人可能都善良，也可能都不愿承认自己的需要。不要把关系纠缠等同于全员血缘、三角恋、黑历史。

试写三个不同压力下的短场景：普通相处、愿望受阻、机会出现。人物是否能产生不同动作？若每场都要靠外部事故推进，先修关系发动机，不继续堆世界观。

## 2. 选择结构，而不是服从结构名词

| 结构 | 适合要实现的体验 | 代价与常见失效 |
|---|---|---|
| 线性 | 精准的情感积累、视角限制、连续演出 | 不要为了有交互而添加廉价按钮；注意阅读变化 |
| 共通线＋人物路线 | 同一处境在不同关系中走向不同结果 | 路线不能只是换恋爱对象后复用同一人格与冲突 |
| 局部分支后汇合 | 表达、局部行动和情绪质感的参与 | 汇合必须携带已经改变的状态，不能全部遗忘 |
| 多视角 | 相互误解、并行行动、有限信息 | 不把每个切换都用于解释刚刚看懂的事 |
| 多路线认知拼图 | 改变前一条路线的理解 | 保留旧路线的情感价值，避免“此前都是假的” |
| 世界内循环 | 同一条件中的试错、损耗与改变 | 主角记忆规则、物品复位与代价必须明确 |
| 跨存档解锁 | 玩家经验成为入口条件 | 系统记忆、玩家知识和人物记忆必须分别定义 |

混合结构可以使用，但先说清每种结构承担什么。新作信息不足时先采用最简单能承载体验的骨架，不默认为多周目真结局。

## 3. 大纲的最小有效粒度

每章记录：进入处境、主要愿望、阻力或共同活动、关键动作、退出变化、明线进展、暗线变化、生活/趣味内容、重要依赖。

章节可以暂停主线，继续建立一个关系或一种地方生活。单章闭环适用于章节案件、副本等结构，不强制所有长篇切成“问题—解决—揭露大谜团”。

大纲中的转折写成行为：“她把备用钥匙留给第三个人”，而不是“她的信任开始动摇”。后者可以作为意图，不能独自承担剧情。

## 4. 伏笔与信息释放

维护“真实事件—角色版本—玩家展示—可能误读—之后验证”的对应。关键推断至少能在当前可用信息中成立。红鲱鱼应有自身原因，不仅为欺骗读者存在。

重要承诺可以是线索、关系、意象或形式承诺。标注它要求的是解释、兑现、变形还是有意悬置。不要让所有细节都必须回收；明确悬置与漏写的差别。

同一事实的第二次出现应增加一项东西：来源可信度、行动后果、人物立场或意义变化。纯重复“这很重要”通常应删减。

## 5. 终局逆推

先试写关键行动，再逆推它需要的能力、关系、物件、信息和机会。逐项找到前文建立位置。允许高潮中出现意外，但解决核心困境的关键条件不应只在需要时凭空出现，除非作品有明确的寓言或荒诞契约。

角色可以失败、退步、拒绝成长。结局需要回应作品的主要承诺，不一定解释所有世界史，也不必用旁白给选择判分。

## 6. 规模与制作

用场景、角色造型、背景、CG、配音、特殊状态及路线独占演出来估算新增负担。人物数量不是固定配额；临时角色未必需要完整立绘。

控制分支成本可用局部汇合、共享事件不同关系状态、只在关键场景分流。省预算不能抹掉选择，增加预算也不能自动增加故事价值。

## 交付

提供可执行的大纲与少量样段，标记确定项和暂定项。用户已要求正文时，以上过程只作为短的内部工作记录，不连续交付设定讨论来代替写作。
