# Visual Novel Writing

**一个面向 Codex 与兼容 Agent Skills 宿主的视觉小说写作 skill**。帮助 agent 从构思、场景成稿、续写与修订，走到分支逻辑和玩家阅读路径检查。适用于视觉小说、Galgame 和文字冒险；线性作品与多路线作品都可以使用。

技能主体以中文编写，但会按用户要求保留或切换稿件语言。当前版本：**0.33.0**。

## 为什么做这个 skill

写 VN 不只是写一段好看的对白。一个场景可能同时要推进眼前行动、呈现人物关系、管理玩家已知信息，并为选择、条件文本或后续路线留下可读的因果。把场景写得“逻辑上说得通”，也不等于玩家会觉得它有趣、可信或值得继续读。

这个 skill 给写作 agent 一套可复用的工作方式：**先明确本次交付，再进入实际正文；先检查因果与连续性，再沿玩家真正会读到的路径阅读；用场景和反馈验证规则，而不是把案例变成固定模板**。它偏向交付可用文本，不会把每个写作请求都改成世界观讨论或抽象建议。

它不会替作者选定题材、文风、路线数量或结局结构，也不要求所有选择都影响长期数值。项目现有设定和用户明确要求优先于 skill 的一般建议。

## 可以用它做什么

| 任务 | 预期交付 |
|---|---|
| 从零构思或搭建大纲 | 有人物驱动的方案、结构骨架，以及用户需要的关键场景样稿 |
| 写一场、下一章或续写 | 接得上已有上下文的实际场景正文，而不只是梗概 |
| 修订一段或全稿 | 有优先级的诊断、根因说明、实际修改稿，以及必要的前后文同步 |
| 设计选项、路线或合流 | 选项表达的玩家意图、状态与知识差异、合流条件和可读后果 |
| 检查连续性和玩家路径 | 人物知道什么、关系如何变化、玩家读到什么，以及每条路径如何成立 |
| 整理演出意图 | 台词、动作、画面/声音提示与场景功能之间的关系；不把文本 cue 当成实机效果 |
| 从作品案例提炼写法 | 带来源、观察、推断、适用条件、反例和迁移练习的候选技法卡 |

## 它怎样工作

1. **读取已有项目资料**。沿用已有设定、人物声音、正史和格式约定；只问当前任务真正缺少的信息。
2. **明确场景要改变什么**。识别人物当下目标、阻力、掌握的信息，以及场景结束时的行动或关系变化。
3. **写或改实际文本**。用户要场景就交场景；用户要建议就先给可定位的诊断，不擅自覆盖原稿。
4. **检查因果和交互**。确认行动有依据，选项表达的参与方式清楚，路线状态与合流信息没有互相矛盾。
5. **按玩家路径读一遍**。逻辑检查与阅读体验分开：检查文本是否成立，也检查节奏、人物辨识度、解释量和继续阅读的动力。
6. **交付并说明变化**。给出可直接使用的正文或文件，并简述重要改动及尚未验证的部分。

这是任务导向的工作流程，不是每次都要逐项填写的问卷。小任务保持小范围；只有涉及的部分才读取参考资料或模板。

## 快速开始

在 Codex 项目目录运行：

```bash
mkdir -p .agents/skills
git clone https://github.com/kantegger/visual-novel-writing.git .agents/skills/visual-novel-writing
```

跨项目使用时，可安装到用户级目录：

```bash
mkdir -p "$HOME/.agents/skills"
git clone https://github.com/kantegger/visual-novel-writing.git "$HOME/.agents/skills/visual-novel-writing"
```

安装后在支持该发现路径的 Codex 环境中用 `$visual-novel-writing` 调用。若没有自动发现，可在对话中明确要求 agent 读取该目录的 `SKILL.md` 并按相关参考执行。其他 Agent Skills 宿主的安装位置和触发方式以宿主文档为准。

### 提示词示例

```text
$visual-novel-writing

读取当前项目的故事大纲、人物设定和第二章正文。
本次只写第三章开场，不重做全书结构。
保留既定人物语气和已经确认的剧情事实。
写出可直接进入稿件的场景正文；检查人物目前掌握的信息和本场因果，
最后删去重复解释。把结果保存为 chapter-03-opening.md，并简述关键改动。
```

不必先把所有模板填完。把现有材料和本次边界告诉 agent，再明确交付物即可。

### 参考资料按需读取

- `structure.md`：从构思到章节骨架。
- `scene-craft.md`：场景目标、人物行动、对话应答和日常互动。
- `interaction.md`：选择、路线状态、短分支和合流。
- `continuity.md`：人物知识、关系、物件和跨场景一致性。
- `direction.md`：画面、声音、动作和观众反馈的文本组织。
- `quality.md`：逻辑检查、玩家路径阅读与证据等级。
- `revision.md`：诊断、优先级、局部改写与前后文检查。
- `corpus-techniques.md`：不同作品里的局部案例、迁移条件和反例；不是风格规范。

## 可选的 VNMD 工具

一般 Markdown 写作不需要脚本。若项目需要显式标记节点、条件和选项，可尝试本包的 **VNMD-0.1** 格式及 `scripts/vnmd.py`，用于检查结构、追踪选择路径或抽样状态。

VNMD 是本项目的轻量文本约定，不是行业标准或游戏引擎格式。它不替作者判断场景是否好看，也不保证兼容某个引擎。脚本使用 Python 3.10+ 标准库，不访问网络或外部模型。

从仓库根目录运行：

```bash
# 运行 VNMD 工具单元测试
python -m unittest discover -s tests -v

# 检查示例文件
python scripts/vnmd.py lint examples/umbrella.vnm.md --state examples/umbrella.state.json

# 沿给定选择路径追踪示例
python scripts/vnmd.py trace examples/umbrella.vnm.md --state examples/umbrella.state.json --choices examples/umbrella.path.json

# 用固定随机种子抽样示例状态
python scripts/vnmd.py sample examples/umbrella.vnm.md --state examples/umbrella.state.json --runs 200 --seed 17
```

输出和未覆盖情况应按项目需要检查；工具通过不代表剧本质量通过。

## 语料案例与来源

技法卡从视觉小说及其他叙事游戏的局部文本中提炼，明确区分“文本实际呈现了什么”和“编辑者认为它可能产生什么效果”。每张卡还列出适用条件、失效方式和新写迁移练习；单个片段不会自动变成普遍规则。

本仓库**不包含或托管完整游戏脚本、图片或音频**。技法卡只保留必要的短文本指涉、转述和评论。作品名称和卡片编号见 [`references/source-index.md`](references/source-index.md)；索引只做来源归属，不表示相关作品、文本或商标由本项目所有。引用位置属于特定文本版本，翻译稿或提取稿不能单独证明原语言写作、实机演出或玩家实际感受。

## 评测状态与边界

仓库包含 16 个写作任务和 6 个触发边界，供使用者做可复现的评估。它们是评测输入，不是成绩报告。这个版本没有独立模型 A/B、盲评、真实读者测试或游戏引擎实机验证，因此**不能据此保证输出一定精彩，也不能声称 skill 已经被证明能提升所有作品的质量**。

它的价值在于让 agent 更有章法地完成实际写作、检查 VN 特有的状态与阅读路径，并减少把局部案例误当成硬性审美规则的风险。最后的取舍仍应回到具体项目和读者反馈。
